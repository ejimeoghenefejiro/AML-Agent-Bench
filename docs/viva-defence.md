# Viva defence: likely examiner questions

> Prepared answers for the questions an examiner is most likely to ask about
> the narrowed, evidence-traceability-centred scope. Companion to
> [docs/demo-script.md](demo-script.md) (what to show) — this is what to say
> when challenged on why the scope is what it is.

| Examiner question | Defensible answer |
|---|---|
| What exactly is novel if precision and recall already exist? | The novelty is not F1 itself. It is the operationalisation of evidence traceability for autonomous AML investigations, together with its validation: a formal claim–evidence model, annotation protocol, failure taxonomy, controlled benchmark tasks, validity evidence, and empirical study across agent configurations — see [docs/evidence-traceability-framework.md](evidence-traceability-framework.md) and [docs/validation-plan.md](validation-plan.md) for what is validated today versus planned. |
| Why is this a PhD rather than a software project? | The software is the research instrument. The doctoral contribution lies in construct definition, measurement design, validation, experimental analysis, and generalisable findings about evidence traceability — see the seven contribution classes (C1–C7) in [docs/research-problem.md](research-problem.md#expected-contribution-to-phd). |
| Why remove hallucination? | Unsupported or fabricated content remains measurable, but it is treated as a [traceability failure](evidence-traceability-framework.md#traceability-failure-taxonomy) (`unsupported_claim`, `invalid_reference`) rather than requiring a separate hallucination construct. This reduces scope and improves conceptual coherence — see [Why the research had to be narrowed](research-problem.md#why-the-research-had-to-be-narrowed). |
| Why remove bias? | Fairness requires a separate set of protected-group assumptions, counterfactual designs, and statistical questions. It is important but not necessary to answer the core traceability question, and attempting both would have recreated the original scope problem. |
| How will you know your gold evidence is correct? | Through a written annotation codebook, independent annotators, adjudication, agreement statistics, and explicit representation of multiple acceptable evidence sets where necessary — see [docs/evidence-annotation-protocol.md](evidence-annotation-protocol.md). None of this has been executed with real independent annotators yet; the current gold set is honestly labelled single-author (see its "Current status" section). |
| What if an agent reaches the correct conclusion but cites poor evidence? | That is a central research case, not an edge case. The benchmark's own discrimination fixtures (`validation/gold/discrimination/*/04_incorrect_conclusion_plausible_explanation.json`) construct exactly this scenario and show that citation-grounding metrics alone cannot catch it — the thesis explicitly tests the proposition that task performance and evidence traceability are related but non-equivalent (H4). |
| Why AML specifically? | AML investigations are evidentiary, multi-record, and high-stakes. Claims often need to be justified using transaction-level and network evidence, making the domain particularly suitable for traceability research — see [docs/research-problem.md](research-problem.md#why-this-matters). |
| What is the role of regulation? | Regulation motivates documentation and human review, but the benchmark does not certify compliance. It generates traceability evidence that may inform governance processes — see [assurance/README.md](../assurance/README.md#positioning-relative-to-the-phd)'s "Positioning relative to the PhD" section, added specifically so this claim is never overstated in generated output. |
| Why use autonomous agents rather than ordinary LLMs? | The research concerns systems that retrieve records, use tools, and construct multi-step investigative outputs. Their evidence chains include interaction with data and tools, not just text generation — the [agentic gap](research-problem.md#research-gap) in the literature review. |
| How will you show generalisability? | By varying task families, data conditions, models, architectures, and evidence complexity (see [docs/experimental-design.md](experimental-design.md)), while explicitly stating the external-validity limits of synthetic/public AML data (see [External validity](validation-plan.md#external-validity) in the validation plan) — not yet demonstrated, stated as a limitation, not implied away. |
| What's actually built versus still a research design on paper? | See [docs/research-scope-mapping.md](research-scope-mapping.md) for the honest, component-by-component answer — it is kept up to date rather than being a one-time snapshot, precisely so this question always has a current, checkable answer. |

## What examiners will actually probe, beyond the scripted Q&A

The table above answers the questions likely to be asked directly. What an examiner actually tests in the room is whether the candidate can extend these answers under pressure — a follow-up on H4's discordant cases, a request to walk through the claim-evidence graph model live, or a challenge on why `attribution_ambiguity` is the one failure type with genuinely zero detection today. Rehearse from the underlying docs (`evidence-traceability-framework.md`, `validation-plan.md`, `experimental-design.md`), not from this table alone — the table is a starting point, not a script to recite.
