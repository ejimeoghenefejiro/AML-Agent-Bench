# Task 007 annotator package — v1 (frozen 2026-08-29)

This is the complete, self-contained package for an independent annotator
working on task-007's material-claim gold evidence (v0.3 validation-priorities
item 1: moving task-007's claim-level annotation from single-author to
multi-annotator). Read `INSTRUCTIONS.md` first.

## Contents

| File | Purpose |
|---|---|
| `INSTRUCTIONS.md` | What to do, in full, including what evidence identifiers look like and what "material claim" / "required" / "acceptable alternative" mean. |
| `prompt.md` | The exact brief a candidate AI agent receives for this task — gives you the investigative question, unmodified. |
| `case_data/` | Every raw source file, exactly as the case is built from: `transactions_primary.csv`, `transactions_correspondent.json`, `transactions_archive.parquet`, `relationships.graphml`, `case-notes.md`, `case-definition.json`. |
| `template.json` | The file to fill in and submit — schema documented in `AmlAgent.Evidence.GoldClaimAnnotationReader`. |

## What was deliberately excluded, and why

- `evidence-annotations.json` (task-007's current single-author gold evidence
  — the exact thing this annotation round exists to independently check).
- `expected-behaviour.md` (the answer key: correct victim/mule/exit
  identification and which innocent accounts must be cleared and why).
- `rubric.json` (scoring criteria that would bias an annotator toward
  matching a rubric rather than reasoning independently from evidence).

This exclusion is enforced by construction, not just documentation
discipline: this directory is generated by copying an explicit whitelist of
source files (see the exclusion test in
`tests/AmlAgent.Tests/AnnotatorPackageTests.cs`, which asserts none of the
three files above are present anywhere in this package).

## Freezing and versioning

This package is v1, frozen 2026-08-29. If the annotation protocol,
instructions, or case data ever need to change, the change produces a new
`validation/annotator-packages/task-007-v2/` directory — this one is never
edited in place once an annotator has started working from it, so every
annotator's submission is always traceable to a specific, unchanging
instruction set (`docs/evidence-annotation-protocol.md`'s own "annotation
provenance" requirement: annotation version, alongside annotator id and
date).

## Where submissions go

See `validation/annotations/README.md` for the directory convention: raw
per-annotator submissions are preserved permanently and never edited, even
during adjudication.
